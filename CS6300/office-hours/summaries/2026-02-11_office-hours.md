## Topics Discussed

- **A5 format requirements:** No embedded Mermaid diagrams; export diagrams as JPEG and reference from Markdown. Students must copy the full requirements list and annotate each item. No official template for A5.
- **UML tool selection:** No required tool; DrawIO and Canva cited as examples. Any diagram editor is acceptable provided output can be embedded in the submission. AI coding assistants must be disabled when using IDEs (e.g., VS Code) to avoid academic integrity violations.
- **Class and operation placement in UML:** Operations belong to the class that owns the relevant data or is responsible for the described behavior. Design decisions at this stage should cover all requirements without pre-empting implementation-level detail (e.g., UI button behavior).
- **Determining completeness vs. overdesign:** Use requirements as a checklist. Exclude details not yet justified by requirements. Avoid classes, attributes, or operations that are not traceable to a stated requirement.
- **UX vs. aesthetics:** Visual aesthetics are not graded. Functional user experience (e.g., navigation flow) is the relevant criterion.
- **Research discussion — Requirements Engineering conference:** Paula reported on a working group session covering adaptive systems (smart home), human values in software design, privacy, AI-assisted formal specification, and a GitLab extension for automatic requirement–issue traceability.
